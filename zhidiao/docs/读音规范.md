# 历史讲解配音读音规范

本项目的配音前端（GPT-SoVITS v3）对文言、史书句式和古地名里的多音字并不可靠，
需要按词固定读音。所有修正写在项目内
`tools\dabao_batch_tts.py` 的 `SPEAK_FIXES`，
由它在**朗读文本**上替换；
字幕与文稿仍保留原字（脚本 metadata 的 `text` 是原文，`spoken` 才是实际朗读文本）。

## 一、降：投降读 xiáng，下降读 jiàng

文言里「降」表**投降、归顺、使降**时读 **xiáng（第二声）**，表**从高到低**时读
**jiàng（第四声）**。TTS 经常一律读 jiàng，因此要按词组固定：

| 读 xiáng（祥） | 读 jiàng（酱） |
| --- | --- |
| 投降、出降、诈降、纳降、受降、归降、请降、乞降、劝降、招降 | 下降、降落、降低、降温、降雨、降职、降级、降旨、降罪、降临、降生 |
| 不战而降、望风而降、闻风而降、束手而降、开城而降、举城而降、率众而降、弃城而降、兵败而降、势穷而降、献城而降、降于魏/吴/汉/曹/刘/袁/孙/晋 | 降水、降雪、降压、降噪、降耗 |
| 降将、降卒、降兵、降者、降表、降书、降魏、降吴、降汉、降曹、降刘、降袁、降孙、降晋 | 降龙、降服（使降服，jiàng fú） |

注意：
- **不要**单独替换「而降」「降于」「已降」「既降」这类裸词：会把「从天而降」
  （jiàng，下降）「既降生」（jiàng，出生）也读错。只匹配明确的投降词组，
  宁可让作者在稿子里把短语写全，也不要为了省事做全局替换。
- **不要**做全局 `降 → 祥` 替换，会把「下降/降温」也读错。
- 「降服」有两种读法：`xiáng fú` 是投降、屈服；`jiàng fú` 是使屈服。历史叙述里
  按上下文取，默认不改，需要 xiáng 时写成「祥服」并单独确认。
- 字幕用的是原文「不战而降」，只有 TTS 实际朗读的是「不战而祥」，两者在 metadata
  里分开存放，不要拿 `spoken` 字段做字幕。

## 三、为什么要用同音字替换

GPT-SoVITS v3 的中文前端用拼音/多音字模型，但它对文言句式和专名会误读；本项目
不修改模型，而是在送进 TTS 之前把目标词替换成**同音、常用、不会被多音字规则改写**
的字（降→祥、彧→玉、郃→合），让模型直接读到正确音节。替换只影响朗读，不影响字幕。

## 四、维护规则

1. 只做**词组级**替换，不做单字全局替换；`SPEAK_FIXES` 按表中顺序逐条替换，
   新增词条时要把长词组写在短词组前面。
2. 新增词条先去查史书/辞书注音，确认在**这个历史语境**里的读法，再写进
   `tools\dabao_batch_tts.py` 的 `SPEAK_FIXES`。
3. 改完用 `tools\tts.cmd` 合成一句包含该词的试听句，确认 metadata 的 `spoken`
   字段是预期替换、`text` 仍是原文；不要拿 ASR 文字判断多音字，ASR 不区分同音字。
4. 每部片的专名如果不在表里，先在 `content/<slug>/` 的口播稿上标注拼音，确认后
   再加入全局表；不要把只对一部片成立的读法硬塞进全局。

## 五、同音替换会反噬：必须按「分段后的上下文」验证

2026-10-22 实测教训：**同音字不是安全牌**。GPT-SoVITS 的中文前端是 G2PW
整句推理，同一个字在不同上下文、不同分段里会取不同读音。

- 「嫪毐」原字在「平定嫪毐叛乱」里本来读对 lào；换成同音字「涝」之后，
  G2PW 把「涝」判成 **liáo**，反而读错。最终换成「烙」才稳定。
- 验证时**不能只测孤立词**，要把它放回真实句子，并且按配音脚本同样的
  78 字分段、按标点切句后再跑 G2P——整句测和分段测结果可能不同
  （「张角」整句读 jiǎo，切段后读 jué）。

审计工具（与 TTS 走同一条 G2PW 路径，不是用 pypinyin 猜）：

```bash
vendor/gpt-sovits/.venv/Scripts/python.exe tools/audit_pronunciation.py \
  --slug <slug>
# 输出 output/<slug>/读音审计.txt：
#   一、读音不在字典里的硬异常
#   二、多音字所在词（去重，实读 + 上下文）
#   三、多音字逐处清单
```

改完 `SPEAK_FIXES` 必须重跑审计，逐条确认「实读」列变成了目标读音；
新增替换要放在原有短词之前（长词组优先）。
