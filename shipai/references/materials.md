# 素材规则：先搜、人眼挑、按 id 下

实拍素材这条链最贵的不是下载，是**挑**。让模型自己从口播稿生成英文关键词去拉素材，命中率很低——本次实测，模型生成的词拉回来的是雪山瀑布、松林、海滩，一条玛雅画面都没有。所以 shipai 把这一步拆开：机器只负责「搜出候选」和「按 id 下载」，挑哪几条由人定。

## 检索策略

1. **用通名，不用专名**。Pixabay 的视频库对中文题材几乎只有通名有货：

| 关键词 | 实测命中 |
|---|---|
| `mayan ruins` | 500 |
| `jungle temple` | 500 |
| `ancient stone ruins` | 500 |
| `maya stone carving` | 500 |
| `mayan pyramid` | 170 |
| `tikal` / `chichen itza` | **0** |

2. **一次查 3–5 个词**，`|` 分隔，`per_page 8`，看命中量再决定要不要换词。
3. **看候选四件事**：时长（≥ 4 s 才够一个镜头）、尺寸（源越大裁竖屏越有余量）、标签（判断画面内容）、id（后面下载认它）。
4. 候选落盘 `materials/candidates.json`，便于二次挑。

## 下载与排序

```powershell
& $py scripts\shipai.py material 004_玛雅巨人文明 --ids 35423,144043,144042,22200,281134
```

- **给 id 的顺序就是拼接顺序**（`--video-concat-mode sequential`），所以挑的时候就要按镜头语言排好。
- 下载走 `large` 尺寸源文件；Pixabay 视频 API 必须带浏览器 `User-Agent`，否则 403。
- 文件命名 `pixabay_<id>.mp4`，清单 `materials/materials.json`（`files` 数组即顺序）。

## 排序原则（本次实例的实践）

一条 17.9 s 的片子用了 5 段、每段 4 s：

| 顺序 | id | 画面 | 为什么在这 |
|---|---|---|---|
| 1 | 35423 | 危地马拉丛林里的金字塔 + 茅草棚 | 开场要「遗址在丛林里」，一眼定题 |
| 2 | 144043 | 石构细部 | 接「它把一年算成…」的细节段落 |
| 3 | 144042 | 石墙与台阶 | 承接农业/工具的落差 |
| 4 | 22200 | 祭祀鼓手 + 现代游客 | 讲「老百姓」时给一个人味镜头 |
| 5 | 281134 | 太阳金字塔远景收尾 | 最后一句「本身就离谱」需要一个开镜 |

规律：**开场给全景定向，中段给细节与人的痕迹，收尾回到大景**。素材不够贴切时，宁可让「人」的镜头承担情绪，也不要拿风景硬凑。

## 已知问题

- **横屏素材进竖屏是 cover 裁切**：1920×1080 源裁成 1080×1920 会切掉左右两侧，先 `probe` 或抽帧确认主体没被裁掉。
- **画面与台词对不上时不要硬凑**：本次第 4 段「祭祀鼓手 + 游客」和「老百姓住的却是泥巴糊墙」并不完全贴，属于可接受的次优——记录在案，下次同类段落优先找民居/茅屋类素材。
- **版权**：Pixabay License 可商用、无需署名，但不要暗示画面里的人物为你代言；有清晰可识别人物的镜头（如本次游客）尽量避免特写。
