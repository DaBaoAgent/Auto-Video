## 〇、结论先行（TL;DR）

1. **不存在"一键全自动"的成熟开源项目**，但有一块几乎为本项目而生的开源引擎：**`yazelin/battlefield-editor`（MIT）**。它的六个范例战役直接包含 **赤壁 / 官渡 / 垓下 / 淝水 / 水淹七军 / 水淹下邳**，自带 AI 编写 SOP、四道机器质检关、CC0 音乐音效库、视频合成管线。
2. 该引擎**已本机实测通过**：克隆 ✓、数据校验 PASS ✓、无头浏览器渲染出真实战场画面（0 报错）✓。见 `docs/screenshots/`。
3. 推荐路线 = **以 battlefield-editor 为渲染内核的"组装式"自研**：引擎（已有）+ 编剧层（自研）+ 配音层（edge-tts → 豆包/GPT-SoVITS）+ 合成层（ffmpeg）+ 发布层（已有管线）。**不推荐从零写引擎**。
4. 需要开发的只有三块：① 主题 → 20 分钟剧本的"AI 编剧"；② 全片自动录制导出；③ 全环节自动串联。预计 **1-2 周出 MVP，3-4 周出可发布的 20 分钟成片**。
5. 备选引擎 `keithligh/cinematic-3d-battle-engine`（MIT，写实卫星地形风）已同步实测跑通，可作近现代战役 / 风格 B 的第二产线。

## 一、需求拆解（6 个环节）

| # | 环节 | 具体内容 | 现状 |
|---|------|---------|------|
| 1 | 编剧 | 主题 → 史料调研 → 20 分钟口播稿（约 5,500-7,000 字）+ 分幕脚本（每幕：标题/旁白/运镜/事件/特效） | ❌ 需自研（我们最擅长） |
| 2 | 数据打包 | 分幕脚本 → 战场数据包（六层 JSON：阵营/地形/建筑/单位/场景/音频） | ✅ 引擎自带契约 + AI 编写 SOP |
| 3 | 渲染 | 3D 沙盘推演动画（地形/河流/阵营单位/行军路线/火攻特效/电影运镜） | ✅ 引擎直接可渲染 |
| 4 | 声音 | 分幕旁白配音 + 字幕 + BGM + 音效（含自动闪避混音） | 🟡 引擎有框架；配音升级需选型 |
| 5 | 合成 | 全片录制 + 拼接 + 字幕烧录 + 混音 | 🟡 引擎有"预告片管线"，全片导出需扩展 |

## 二、核心引擎（可直接用）—— 本次调研最大发现

### 2.1 ⭐ 主推：yazelin/battlefield-editor

- **仓库**: https://github.com/yazelin/battlefield-editor ｜ **★45** ｜ **MIT** ｜ 2026-06-16 创建 / 2026-08-18 最后更新 ｜ 14 forks
- **在线演示**: https://yazelin.github.io/battlefield-editor/ （赤壁：`play.html?pkg=packages/chibi/battlefield.json`）

**它是什么（详介）**：数据驱动的单文件 3D 历史战场引擎——"每一场战役都是一份数据包，引擎只负责演出；AI 编写数据、人负责验收与微调。" 它由作者从"3D 赤壁之战"演示（red-cliffs-3d，10★）逐步抽象而来：引擎、数据契约（JSON Schema）、验证工具与 AI 编辑 SOP 构成一套完整体系。仓库内置六份完整的中国历史战役数据包——**赤壁之战**（水战：9 幕 + 旁白语音 + 音乐 + 音效）、**官渡之战**、**垓下之战**、**淝水之战**（该包由"零上下文 AI agent 照 SKILL 自动编成"，是 AI 全自动编写可行性的直接证据）、**水淹七军**、**水淹下邳**。所有内容——阵营配色与旗帜、参数化地形（河道 Catmull 控制点/丘陵/色带 → 连续高度场）、建筑（城/营/隘口/渡口）、单位（陆军/水师方阵）、多幕场景（运镜 shots + 布阵 + 行军 + 特效 + 事件 + 计策 + 战斗 + 终幕）、音频（配乐/旁白/字幕/音效 cue）——全部写在 JSON 数据里，引擎代码永远不用改。特效词表覆盖 `volley`（箭雨）、`ignite`（燃烧）、`flood`（水攻：水位上涨/退去、船只随水浮、可指定决堤口让水锋从缺口推进淹没）、`shake`（震动）等历史战争"名场面"所需。它还自带**本地所见即所得编辑器**（在战场上直接拖单位、改河道走向、调洪水高度、换 glTF 模型、就地重新生成旁白语音），以及一条**零成本视频合成管线**（Playwright 录屏 → edge-tts 旁白 → ffmpeg 合成 16:9 / 9:16 / 4:5）——其核心洞察是："**引擎本身就是电影运镜演出器 → 屏幕录它，根本不用'生成'视频**"。AI 编写流程（`skills/author-battlefield/SKILL.md`）定义了清晰边界：**AI 编数据、过机器四关；人只判机器判不了的三件事——空间正确、电影感时序、感官品质**——与我们的"宝哥终审"流程天然契合。

**关键规格**：
- 技术栈：Three.js r160，零构建、单 HTML 引擎（play.html，约 2472 行），静态服务即可跑
- 数据六层：`factions / terrain / structures / units / scene / audio`（各带 JSON Schema + 跨文件引用校验）
- 质检四关：`validate-data`（零依赖）→ `residue-scan`（查复制残留）→ `render-check`（headless 逐幕截图 + 0 console error）→ `audio-check`（旁白音长 ≤ 幕长）
- 素材库：**CC0 音乐库 74 首 + CC0 音效库 22 个**（含 mood 评分与出处），`assign-music` / `assign-sfx` 自动指派；另有**题材影视原声池** `audio.json#music.ost`（含 OST/BGM 名单），成片可逐幕改用（如三国题材用 2010 版《三国》OST），`assign-music` 支持 `ostNN` 池 id
- 换配乐免重渲：`tools/reburn-bgm.mjs`（重做音轨 + 画面 `-c:v copy`）；音轨合成逻辑抽到 `tools/lib/film-audio.mjs`，渲染与重烧共用。⚠️ 影视原声非 CC0，有平台 Content ID 风险，出处与授权须记入 CREDITS
- 旁白：`narration/generate.py`（edge-tts 双声 + 字幕 cues + 破音字 SUBS 机制；已踩平"將+人名"断句等坑）
- 制作流程：`new-package.mjs` 脚手架长出"最小绿灯包" → 依序编六层 → 过机器四关 → 人验收
- 编辑器：`node tools/editor-server.mjs` → localhost:8090（仅本机显示编辑面板，公开页只读）

### 2.2 备选：keithligh/cinematic-3d-battle-engine

- **仓库**: https://github.com/keithligh/cinematic-3d-battle-engine ｜ **★11** ｜ **MIT** ｜ 2026-09-23 更新
- 姊妹成品站：Hong Kong 1941（46★）、D-Day Normandy 1944

**它是什么（详介）**：写实风格的"自播放 3D 战争纪录片引擎"——把任意历史或虚构战役渲染成自播放纪录片：真实的 SRTM 高程与 Sentinel-2 卫星影像按真实经纬度投影到比例尺；一个状态机"导演"自动播放分镜（可随时抓取镜头自由观察，松手自动恢复）；军队调动、时期旗帜、双语旁白字幕、天气与昼夜循环全部由数据文件（`data.js` + `flags.js`）驱动，引擎模块永不改动。它专为 AI agent 编写而设计（内置 PROMPT.md / AGENTS.md / PLAYBOOK.md，口号"你指挥和把关，agent 干活"），且数据契约**要求必须填写史料来源**（`notes.sources`，"不引用来源的战役不予渲染"）——这个设计非常值得借鉴到我们的"史实审核关"。地形/影像瓦片来自 AWS Terrarium（SRTM/USGS，公共领域）+ EOX Sentinel-2（CC BY 4.0），无需 API key。

**本机实测记录**：✅ 克隆成功；`node tools/validate.mjs` → `OK`；本地服务 HTTP 200；**40/40 张真实地形/卫星瓦片全部下载成功**。

**局限**：现代卫星地貌（适合近现代战役或"实景风"，古代战场地貌不匹配）；11★ 很新；无视频导出（需录屏）；界面英文为主。

### 2.3 两个引擎怎么选

| 维度 | battlefield-editor（主用） | cinematic-3d-battle-engine（备用） |
|---|---|---|
| 视觉风格 | 低多边形 3D 沙盘 + 水墨色带（≈"沙盘上的战争"风） | 写实卫星地形（≈硬核纪实风） |
| 年代适配 | **中国古代战役（赤壁/官渡/垓下…已内置）** | 近现代/实景战役 |
| 数据驱动 | 六层 JSON + Schema + 四关质检 | data.js + 契约校验 + 来源必填 |
| AI 编写支持 | **SKILL 级 SOP + 已验证 dogfood** | PROMPT/AGENTS/PLAYBOOK |
| 视频导出 | 有 trailer 管线（需扩全片） | 无（需自建录屏） |
| 结论 | **作为本项目渲染内核** | 第二产线 / 近现代题材 |

**NarratoAI（详介）**：11.3k★ 的 AI 影视解说自动化（文案生成 + 配音 + 字幕 + 剪辑），与用户的纪录片解说是同一工作流家族；本项目与其差异点在"地图推演渲染"而非"原片剪辑"，但它的"文案-配音-字幕-成片"串联经验可参考。

## 四、推荐总体架构（组装式）

```
[主题输入：如"赤壁之战"]
   │
   ▼
① 编剧层（自研·Hermes + DeepSeek）
   史料调研（gongzuo 秒查 / Viking / 汇编）→ 20 分钟口播稿（5,500-7,000 字）
   → 分幕脚本 JSON（每幕：标题/旁白/运镜/事件/特效/时长）
   → 【史实引用核对关】+【宝哥终审关】
   │
   ▼
② 数据层（battlefield-editor 六层 JSON）
   AI 编写 factions→terrain→structures→units→scene→audio
   → 机器四关：validate → residue-scan → render-check → audio-check
   │
   ▼
③ 渲染层（bfe 引擎 · Three.js）
   全片自动录制（Playwright recordVideo / CDP）→ 16:9 + 9:16 母版
   │
   ▼
④ 音频层
   分幕旁白 TTS（edge-tts → 升级豆包/GPT-SoVITS）→ 字幕对齐（whisperX）
   → 配乐/音效（CC0 库自动指派；成片可逐幕改用 `music.ost` 影视原声池）→ ffmpeg 混音（BGM 低于人声 ~16dB；换乐用 `reburn-bgm.mjs` 免重渲）
   │
   ▼
⑤ 合成层（ffmpeg）
   全片拼接 + 竖版字幕烧录 + 封面 → 成片 MP4（1080p）
   │
   ▼
⑥ 发布层（已有管线）
   douyin-auto-publish / bsk → 多平台 + QQ 通知
```

**每层的开发归属**：① 新开发（核心工作量）② 引擎已备（写 SKILL/SOP 自动化壳）③ 新开发（录制扩展）④ 半新（接线 + 升级）⑤ 新开发（套模板）⑥ 现成复用。
