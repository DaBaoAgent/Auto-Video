## 一、结论先行

**内容层 A，包装层 C-。**

- 内容层是真的能打：33 条管线 / 11 工位 / 32 条 `live`，`validate.py` 报 `OK 契约一致`，33 条 `meta.entry` 全部指向真实存在的入口文件，每条 `SKILL.md` 约 195 行，写的是确定性渲染、字幕贴语音、镜界落静音窗、零频闪预算、验收门禁——这套东西在开源视频项目里**极少有人写到这个颗粒度**。
- 包装层的失败点**发生在安装之前**。一个陌生人打开仓库，30 秒内看不到一张图、拿不到一条能跑的命令、也不知道自己需要 Chrome / Node / ffmpeg / GPT-SoVITS 里的哪几个。高星项目的本质不是"代码多牛"，是"陌生人的第一次成功体验"；这里的第一次成功体验，需要先拥有作者那台 Windows 机器。
- 一句话差距：**这是一个"作者的私人车间 + 一个做得不错的作品集网站"，还不是一个"可以被陌生人安装、验证、贡献的开源项目"。**

## 三、差距到底在哪（7 条，按杀伤力排序）

### D1　陌生人的第一次成功体验缺失（最致命）

高星项目的第一屏都回答同一个问题：**"我复制哪一行，就能看到东西？"**

- MoneyPrinterTurbo：`pip install mpt && mpt webui`，或 `docker compose -f docker-compose.release.yml up` 拉预构建镜像，还有 Colab 徽章、Windows 一键包、PyPI 包、Agent 一句话接入——**五个入口，每个都是零配置**。
- Remotion：`npx create-video`。
- Auto-Video：`python jianying/scripts/jianying_shotcraft.py new myfilm`，然后需要 Node 18+、ffmpeg、ffprobe、numpy、Chrome、外加 GPT-SoVITS 才能配音。而 41 个脚本里写着 `D:\...` 和 `C:\Users\Administrator\...\chrome.exe`。

**代价**：任何人（包括想 star 的中文开发者）在第一步就退出，star 转化率≈0。
**修法**：挑**一条画法最轻、依赖最少**的管线（`shiliang` 纯标准库 SVG 单页，Chromium 打进镜像里，宿主不用装）做成 Docker 一键 demo；`docker compose run demo` 出 15 秒片。这一条通了，再谈其它。

### D2　把仓库当网盘用

441.5 MB 媒体 + 147.1 MB 字体（大字体重复 5/4/2 份）+ 265.1 MB 死素材入库，没有 `.gitattributes`、没有 LFS、没有 Release assets。

**对照**：MoneyPrinterTurbo 的 18 个样片缩略图**全部**指向 `github.com/harry0703/mpt-assets/releases/download/assets/...`——媒体放 Release 资产，仓库只留代码。
**代价**：`git clone` 变成几分钟级，移动端/弱网直接失败；这正是"路过的人不会 star"的第一道摩擦。
**修法**：媒体迁 Release assets（或独立 `auto-video-assets` 仓库）；删 `showcase/`；字体全局收一份（147.1 → 约 55 MB），缺字再子集化；加 `.gitattributes` 给二进制走 LFS。

### D3　README 是目录，不是门面

852 行、62 KB、正文零图片、英文只有 7 行（846–852）。

**对照**：MoneyPrinterTurbo 首屏是 logo + 一句话定位 + 版本/平台/下载量徽章 + Trendshift/Star-History 社交证明 + `简体中文 | English | 日本語` 切换 + 两张界面预览图，然后才是功能清单。Auto-Video 首屏是标题 + 6 个自造徽章 + 一个链接。

**代价**：中文圈的"看目录"能忍，英文圈和 HN/Reddit 的流量 100% 流失；62 KB 的 README 在手机端要滑很久才看到样片。
**修法**：首屏 = 60 秒成片 GIF（6–10 MB）+ 3×3 样片九宫格 + 3 行命令 + 站点链接；正文压到 200 行内，33 条工位表搬 `docs/pipelines.md`；英文独立成 `README-en.md` 并在顶栏切换。

### D4　没有"产品版本"

0 tag、0 release、0 CHANGELOG，README 里也没有版本徽章。

**代价**：无法引用"我用的是 v0.3"，无法归档"这一版样片"，也无法用"下载量"做第二层社交证明；媒体迁移也缺一个天然载体（Release assets 正好解决 D2）。
**修法**：打 `v0.1.0`，附 Windows/一键包 + 样片 zip；每两周一版，`CHANGELOG.md` 用人话写"这一版多了哪条管线、哪条样片"。

### D5　没有贡献漏斗

CONTRIBUTING、issue 模板、PR 模板、Discussions、CODE_OF_CONDUCT、SECURITY 全无；issues 0、讨论关闭。

**代价**：高星不是"被看到"的结果，是"被参与"的结果。没有 `good first issue`，没有"加一条管线要做的四件事"的可执行清单，路人只能 star 完就走。
**修法**：README 的「加一条新管线要做的四件事」升级成 `CONTRIBUTING.md`（含最小可合并管线模板、`validate.py` 必须过、样片必带）；开 Discussions；给 6–10 个 `good first issue`（补样片、补 spec、改死分幕、修盘符路径都合适）。

### D6　这是 33 份副本，不是一个引擎

`runtime/` 10 份逐字节相同；`timeline.js` 6 份；`make_vo.py` 8 份；41 个文件写死盘符。

**代价**：两个后果。其一，贡献者不知道"该改哪一份"，改一处要改十处——这是"引擎型项目"和"作品集"的分水岭（Remotion / motion-canvas 的高星恰恰来自"一个包，谁都装得上"）。其二，任何一条管线的 bug 都要在 10 个地方复现。
**修法**：抽 `packages/av-runtime`（core / render / bgm / lang / sound / promo），各管线只留 `theme` + `timeline` + `film.json`，用 workspace 引用；路径一律走环境变量 + `pathlib`，禁止盘符字面量。

### D7　自述与现状不一致（信任损耗）

- 仓库描述：`Production-ready ... 5 live, 99 planned`，实际 32 live；"5 live"会让第一次看的人以为大半是画饼。
- `homepage` 未设：About 侧栏没有那个已经做得不错的站点链接。
- Pages 站点缺 `og:image`、favicon、canonical、sitemap：在微信/Twitter/Discord 分享出去是一张白卡。而站点本身的质量（悬停即播、灯箱、筛选、搜索、竖屏横屏）**已经是高星项目的水平**，等于把最好的资产藏起来了。

**修法**：改描述（`32 craft pipelines + 1 TTS frontend · deterministic, code-rendered, no cloud API`）；About 填 homepage；站点补 1200×630 `og:image`（九宫格拼图即可）+ favicon + sitemap。

## 四、别改坏的部分（这几样已经超过大多数高星仓库）

1. **`SKILL.md` 的工艺手册**：每条 ~195 行，讲的是"为什么"而不是"点什么按钮"——确定性 PRNG、镜界落静音窗、零频闪预算、AI 只做静帧不做视频、静帧先验再整片。这是这个仓库真正的护城河，也是最该被英文世界看到的部分。
2. **统一契约 + `validate.py`**：`catalog/pipelines.json` 单一事实来源，CI 里真跑，报 `OK 契约一致`。很多万星项目都没有这层一致性校验。
3. **站点**：悬停即播 + 灯箱有声 + 工位分组 + 筛选搜索，交互完整度高于同类作品集。
4. **33 条真实成片样片**：不是"概念演示"，是能看完整片的作品。对标仓库里，MPT 的样片是模板化生成的，这里的样片是手工艺级别的差异。

结论：**不要为了"更开源"去稀释工艺文档的密度；要做的只是把入口、门面、版本、贡献这四层包装补上。**
