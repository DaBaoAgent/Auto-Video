# 多机同步

三台机器共用同一路径 `D:\@kaifa\Auto-Video`，远端 `https://github.com/DaBaoAgent/Auto-Video.git`（分支 `main`）。改完即推，另一台拉，禁止把同一个改动在两台上各写一遍。

## 同步前先看这三个数

```powershell
cd D:\@kaifa\Auto-Video
git log --oneline -1                 # 本机在哪个提交
git log --oneline -1 origin/main     # 远端在哪个提交
git rev-list --left-right --count main...origin/main   # 左边是本地领先，右边是落后
```

`0 0` 就是一致。只有 `0 N` 才能快进，出现本地领先就先推再拉。

## 标准命令

推送（改完那台）：

```powershell
git add -A
git commit -m "说明这次改了什么"
git push origin main
```

拉取（未改的那台）：

```powershell
git fetch origin main
git merge --ff-only origin/main
```

`--ff-only` 拒绝自动产生合并提交：一旦报 "not possible to fast-forward"，说明两台都改过同一个分支，要先查清再动手，不要硬合。

## 网络坑（GitHub 在国内时通时断）

三台的共同症状：`Connection was reset`、`Failed to connect to github.com:443`、`RPC failed; bad pack header`。**这是抖动，不是仓库坏了**，重试即可，间隔 15–30 秒，通常第 3–5 次能过。

两个致命坑，遇到必须按下面的顺序排查：

1. **代理环境变量把自己坑死。** 机器上常见 `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY = http://127.0.0.1:15715`，那是本地工具的代理，指向它的 TLS 隧道是坏的。git 读这些变量，于是握手失败。先清空再干活：

   ```powershell
   $env:HTTP_PROXY=''; $env:HTTPS_PROXY=''; $env:ALL_PROXY=''; $env:NO_PROXY='*'
   ```

2. **Windows 证书吊销检查离线。** 报 `CRYPT_E_REVOCATION_OFFLINE (0x80092013)` 时，是系统查不到吊销列表，不是证书本身有问题。两个解法，任选：

   ```powershell
   git config --global http.schannelCheckRevoke false     # 关掉吊销检查
   git -c http.sslBackend=openssl ...                     # 或换 openssl 后端，一劳永逸
   ```

   实测 TY 上单关吊销检查仍握手失败，**换 openssl 后端才通**。

一次性重建仓库（TY 上曾只剩空壳时用过，3541 个文件约几分钟）：

```powershell
$env:HTTP_PROXY=''; $env:HTTPS_PROXY=''; $env:ALL_PROXY=''; $env:NO_PROXY='*'
cd D:\@kaifa
git -c http.proxy= -c http.sslBackend=openssl clone --depth 1 --single-branch --no-tags `
    https://github.com/DaBaoAgent/Auto-Video.git Auto-Video
```

`--depth 1` 只取当前快照，体积小、成功率高；代价是没有历史，`git log` 只有一条。日常拉取不受影响，需要完整历史时再 `git fetch --unshallow`。

## 成片不入库

GitHub 单文件上限 100 MB，定稿成片往往 150 MB 上下，`.gitignore` 里 `out/**/*.mp4` 是故意忽略的。所以三台机器的 `out/<编号_片名>/` 里只有字幕、封面、发布信息，**视频文件不在**。

成片要跨机器，走 git 之外的通道（网盘、U 盘、局域网拷贝）。别为了传片子去改 `.gitignore`，那会把仓库撑爆。
