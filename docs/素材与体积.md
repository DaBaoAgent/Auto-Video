# 素材与体积

有人 clone 完发现 `.git` 三百多兆，先解释清楚这些字节是什么、哪些该留、哪些该怎么处理。

## 现在仓库里有什么

| 位置 | 内容 | 体积 | 该不该在 git 里 |
| --- | --- | --- | --- |
| `site/media/` | 88 段压缩样片（每条管线一段）+ 88 张封面图 | 约 101 MB | **该在**：在线样片站靠它，Pages 只能从仓库取 |
| 各管线 `assets/` | 字体、少量贴图、`manifest.js` | 约 147 MB | 部分该在：字体按工程各存一份，删了会破坏老样片可重现性 |
| 历史里的 `showcase/` | 原片 mp4（已从工作树删除） | 曾 265 MB | 不该在：原片走 Release assets |
| `.git` | 历史对象 | 约 322 MB（重写前 662 MB） | 见下节 |

## 为什么 `.git` 这么大

历史上原片、样片预览、字体都被提交过，后来虽然从工作树删掉，**对象仍在历史里**。clone 要把整段历史拉下来，
所以 `git clone` 慢、CI checkout 慢、GitHub 的 `size` 字段也会一直是六七百 MB。

## 怎么瘦身（破坏性，需维护者决定）

```bash
# 需要 git-filter-repo（pip install git-filter-repo）
git filter-repo --strip-blobs-bigger-than 5M --path-glob 'showcase/*' --invert-paths
git push --force-with-lease
```

后果：所有已 fork/已 clone 的副本作废，commit hash 全变，Release 与 tag 需要重新打。**不要在 PR 里做这件事**，
由维护者择期一次性执行，并在 Release 里通知。

## 新东西怎么进仓库

- 代码、配置、模板、文档：直接提交。
- 样片原片（`*.mp4` 未压缩、`*.mov`、母版）：**不进 git**，挂到 Release assets，或在 `site/media/` 放压缩版。
- 字体：优先用系统字体或 CDN（`render.mjs` 会把网页字体缓存到 `~/.cache/auto-video/fonts`）；
  确需内置的，走 Git LFS（`.gitattributes` 已配 `*.ttf/*.otf/*.ttc`）。
- 模型权重（`*.safetensors`、`*.ckpt`）：一律不进仓库，走发布页或用户自备。
- 大 PSD / BLEND 源文件：LFS 或外链。

`.gitignore` 已经挡掉 `showcase/`、`demo/out/`、`**/review/`、`*.preview.gif`、`**/board*.png`。
`.gitattributes` 里把媒体标成 binary，避免 diff 把仓库撑爆；`text=auto eol=lf` 保证跨平台换行一致。

## 做站点用的压缩样片怎么生成

```bash
python tools/build_samples.py --workers 4   # 出视频 + 封面
python tools/build_site.py                  # 重建 site/index.html
```

`build_samples.py` 只写 `site/media/`，不碰原片。想在本地预览站点：`python -m http.server -d site 8000`。
## 重写之后（2026-11-17 实际执行）

- .git：**663 MB → 322 MB**（剔除 showcase/、shouhui 工程产物视频、以及 site/media/ 的 256 个历史旧版本）。
- 代价：**所有 commit hash 变了**，旧的 fork / clone 不能直接 pull，需要重新 clone 或 git fetch --force 后 git reset --hard origin/main。
- GitHub 仓库页的 size 字段会滞后（服务端要等自己的 gc），实际 clone 大小以你本地为准。
- 本地旧对象可回收：git gc --prune=now（我们这台机器执行后从 660 MB 回到 322 MB）。
- 备份：重写前的完整镜像曾留在 `D:\@kaifa\_backup\Auto-Video-mirror-20261117.git`（659 MB），**已于 2026-11-17 删除**；现在要取重写前的历史只能从旧 clone 或 GitHub 的历史提交里找。
