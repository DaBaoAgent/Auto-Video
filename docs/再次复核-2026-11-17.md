## 一句话结论

**内容层还是 A，包装层从 C- 挪到了 B-。** 现在陌生人能在 30 秒内拿到一段能看的片（`python demo/run.py`，
22.7 秒一间 6 秒片），仓库有版本、有 Release、有 Discussions、有贡献漏斗；剩下的差距集中在**体积、第一公里的
「装不上」、以及 23 条管线仍然只能人工接最后一步**——这些不是写文档能补的，要动代码和资产。

## 二、还没做 / 做不了的（按严重度）

### P0 · 挡在「陌生人能跑」前面

1. ~~`.git` 663 MB~~ → **已处理（2026-11-17）**：`git filter-repo` 剔除 `showcase/`、工程产物视频、
   以及 `site/media/` 的 256 个历史旧版本，`.git` 从 **663 MB 降到 322 MB**（剩余主要是字体 52 MB、
   站点样片 101 MB、各工程素材）。所有 commit hash 已变，`v1.0.0` 已在新历史上重打；旧副本请重新 clone。
   实测全新 `git clone`：**54.5 秒、下载 322 MB**（GitHub 页面的 `size` 字段会滞后，别拿它当准）。
   推送时发现的坑：`git-lfs` 的 `locks/verify` 会卡住整条 push，`git config lfs.locksverify false` 即可。
2. **Docker 路径没在本机验证过。** 本机没有 Docker（`Get-Command docker` 为空），`docker/Dockerfile`
   与 `docker-compose.yml` 只做了静态检查。镜像里装了 chromium / ffmpeg / fonts-noto-cjk，
   构建期会自检 3 秒片；但「构建成功」这件事目前没有证据。**这是 Release 里唯一一句没实测的承诺。**
3. **字体 147 MB 没去重。** 字体副本散在各管线工程里，删了会破坏老样片可重现性。
   要做「共享字体 + 构建期拷贝」的重构，得先同意「存档样片不再逐字节可重现」这个代价。

### P1 · 挡在「一条龙」前面

4. **23 / 33 条管线仍不能从选题直接出片。** 现在能一条龙的是 `laolang`、`map` + 8 条模板；
   其余要真实素材（`shipai`、`jilupian`）、高程路线（`chengshi`、`ditu`）、本地模型（`zhidiao`、`tianshu`）、
   管线内 TTS 时间轴（`shiliang`、`xuni`、`dengju`、`xianshiqi`）或者根本不是文案输入（`tuiyan`、`huixingzhen`）。
   把「一个选题走完五步」当宣传语，就得把这 23 条里的「能靠文案 + 免费 TTS 出片」的先捞出来（`caiqian`、
   `pingban`、`shouhui`、`piying`、`shuimo` 大概 5 条有希望）。
5. **104 行 / 44 个文件仍有硬编码盘符路径**（`D:\@kaifa\lemo-opuscar`、`C:\Users\20200\…\Python312`…）。
   其中一部分是 Chrome 路径候选（可接受），但 `bianping.py` 把整个外部工程当 `LIB`、
   `blueprint.py` 直接指到别人的 Chrome 安装路径——这两类在任何别的机器上都会失败。
6. **8 条模板的保底排版只解决「能出片」，不解决「好看」。** 现在是「片头卡 + 序号 + 强调线」的排版，
   和原来那支手绘/漫画样片不是一个东西。要让模板也好看，得给每条画法写一个「卡片 + 画法元素」的组合层
   （比如 pencil 配 `S.figures`、manga 配分格边框），这是纯美术工作量。

### P2 · 门面细节

7. **英文门面仍是 7 行。** README 846–852 行那段 English 基本是占位；真高星标项目是双 README +
   多语 GIF。要做就做 `README.en.md`，别在中文 README 里塞半段英文。
8. **首页没有动态演示。** 头图是三张静帧；高星标项目首屏通常是一段 6–10 秒无声 GIF（体积 ≤ 3 MB）。
   我们的 `demo/out/demo.mp4` 可以直接抽一段做 GIF。
9. **CHANGELOG 只有 v1.0.0 一个版本。** 之后每次合并都该有一行，否则徽章和 Release 会漂。
10. **`showcase/` 目录删了，但 README 与脚本里可能还有引用**（本轮只改了直接提到数量的地方，
     `tools/` 里若还有硬编码 `showcase/` 需再扫一遍）。

## 三、和真正的高星标差在哪（对标数据仍取上轮实测）

| 维度 | MoneyPrinterTurbo（144,090★） | Remotion（73,762★） | Auto-Video（1★，刚发 v1.0.0） |
| --- | --- | --- | --- |
| 第一公里 | `pip install mpt` / Windows 一键包 / Colab / GHCR 镜像 | `npm i remotion` + 官方模板 | `python demo/run.py`（要自备 Chrome/ffmpeg）或 `docker compose run`（未实测） |
| 输入门槛 | 一句话 topic | React 组件 | 一句口播稿（但只有 10/33 条能直接吃） |
| 可复现 | 有随机性 | 代码即真相 | **最强项**：禁随机、参数进 `pipeline.json`、门禁脚本 |
| 资产规模 | 单管线 + 模板市场 | 组件生态 + 文档站 | 33 条管线 / 88 段样片 / 11 工位 |
| 分发 | PyPI、镜像、Release assets、API 服务 | npm、文档、Showcase | 只有 GitHub Pages 站点 |
| 社区 | Issues/Discussions 活跃、PR 多 | 全职团队 + 赞助 | 1 star、0 issue、Discussions 刚开 |
| 体积 | 仓库轻（素材外置） | 4.4 GB（但用 LFS/Release） | 322 MB `.git`（重写后），clone 仍偏重 |

**差距的本质**：他们的护城河是「任何人 10 分钟出片 + 生态」，我们的护城河是「工艺可复现 + 门禁」。
前者靠降门槛，后者靠可验证。现在我们把门槛从「读 195 行 SKILL.md」降到「一条命令」，但 **clone 体积**
和 **Docker 未验证** 两件事，仍然会让一半陌生人在第一步掉头。
