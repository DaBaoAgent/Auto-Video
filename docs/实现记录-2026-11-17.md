# 第三轮体检的 5 件事：落地记录（2026-11-17）

对应 `docs/三轮体检-2026-11-17.md` 里按 ROI 排的那 5 条。每条写：改了什么、怎么验的、还剩什么。

## ① 收编 4 份旧 `render.mjs`

**问题**：15 份 `render.mjs` 里，`shouhui` / `caiqian` / `ditu` / `pingban` 这 4 份是没打过补丁的旧版——没有超时、没有进程回收、路径写死在本机。

**为什么不硬合并成一份**：新旧两套 API 根本不同，合并会把调用方改坏。

| | 新 API（`vendor/bb-video/runtime/render.mjs`） | 旧 API（`--stills/--out/--scale/--duration/--mb/--shutter`） |
|---|---|---|
| 浏览器 | playwright-core 自动拉起 | `shouhui` 那套自建 CDP + 自己 spawn Chrome（Edge 154 上 `puppeteer.launch` 会静默退出） |
| 页面契约 | `window.READY` + `window.render` | `window.__ready` + `window.renderAt(t)` |
| 用它的管线 | 10 条 | `caiqian` / `ditu` / `pingban`（playwright 系）、`shouhui`（CDP 系） |

所以做成「同一 API 各自一个唯一来源」：

- `vendor/bb-video/runtime/render-legacy.mjs`（约 200 行，playwright-core）：给 `caiqian` / `ditu` / `pingban`；
  补了 `BV_FRAME_TIMEOUT`（默认 60s）、`withTimeout` 包住 goto/evaluate/screenshot、`PROCS` 跟踪 + `reap()`
  （Windows `taskkill /PID /T /F`、POSIX 杀进程组）、`process.once('exit')` 兜底、`finally` 里关浏览器/停服务器/reapAll；
  playwright-core 的定位改成 `$PLAYWRIGHT_CORE → 工程目录向上找 node_modules → 全局`，删掉了写死的本机路径。
- `vendor/bb-video/runtime/render-mg.mjs`（约 380 行，puppeteer-core + 自 spawn Chrome）：给 `shouhui`；
  补了 `findBrowser()` 多平台探测、`FRAME_TIMEOUT`（默认 120s）、`seek()/shot()` 超时、`finally` 里 `reap(b._proc)`。
- 4 份管线内副本已删，调用方改成指向唯一来源（`caiqian/ditu/pingban` 的 `RENDER` 常量、`shouhui.py` 的 `RENDER`/`EDGE`）。

**验证**：

```
node vendor/bb-video/runtime/render-legacy.mjs caiqian/projects/029_jia_xueyu --still 2,5   → exit 0，出图 2 张，chrome 残留 0
（同一命令，喂一个永不 window.READY 的页面）                                                → exit 1，报 Timeout 60000ms，chrome 残留 0
node %TEMP%/mg-render-probe/render.mjs --fps 12 --duration 1                                  → 见下（引擎自证）
```

`shouhui` 在本机跑不了完整工程（缺 `vendor/mg-styles-15` 那份样式包），所以只用 640×360 最小页验证引擎本身：
页面 `window.__ready` + `window.renderAt(t)`、自 spawn Chrome、出 mp4、结束后不残留 chrome 进程。

## ② 浏览器 / 字体 / ffmpeg 绝对路径统一

**问题**：120 行绝对路径散在 51 个文件里；10 个脚本各写一份 `CHROME_CANDIDATES`；换台机器就要重改一遍。

**做法**：新建 `tools/platform_paths.py` 作为唯一探测入口：

- `chrome_path()`：`CHROME_PATH / MG_CHROME / PLAYWRIGHT_CHROME / BV_CHROME` → 各平台常见路径 → PATH；
- `require_chrome()`：拿不到就给一句人话错误；
- `font_candidates(names)`：带别名表（`msyh.ttc` → 思源黑体、`STXINGKA` → 霞鹜文楷/龙藏），跨平台不至于 404；
- `ffmpeg_path()` / `ffprobe_path()` / `font_dirs()`。

10 个带 `CHROME_CANDIDATES` 块的脚本（blueprint / goldenage / isometric / laolang / manga / map / parable / pencil / shadow / tapestry）
统一改成 `from platform_paths import chrome_path`。

其余定点修复（都换成了环境变量，取不到才降级）：

| 变量 | 用在哪 |
|---|---|
| `FENGMIAN_DIR` | `laolang` 封面素材目录 |
| `SAMPLES_DIR` | `tools/build_samples.py` 的样片源 |
| `YANDI_DIR` | `piying/tools/` 6 个一次性脚本 |
| `HF_HUB_CACHE` | `shipai/vo_segment.py` |
| `GPT_SOVITS_PRESET` | `jianying/line_tts.py` |
| `BIANPING_LIB` / `BIANPING_PY` | `bianping` |
| `BFE_ALIGN_MODEL` | `tuiyan/transcribe-ref.py` |
| `ZHIDIAO_ROOT` / `ZHIPU_KEY_FILE` | `zhidiao/tools/` |
| `BV_FONT_DIR` / `FONT_DIR` | `platform_paths.font_dirs()` |

**结果**：绝对路径命中从 110 行降到 51 行。剩下的是两类，都不是真问题：

- 正则误报（`I:\s*`、`Peak:` 这类文本片段）；
- `tools/build_fonts.py` 的 `WIN_FONTS`（那是「从 Windows 系统字体目录取字体」的功能本身，必须写死系统路径）。

## ③ 依赖清单 + CI 契约门禁

**问题**：仓库没有一个「装什么才能跑」的地方；也没有任何 CI，所以 15 份 `render.mjs` 里 4 份是旧版这种事只能靠人记得查。

新增：

- `requirements.txt`：直言核心只要 python 3.10+ / node 18+ / 一个 Chrome / ffmpeg，第三方依赖为零；
- `requirements-optional.txt`：配音、字幕、转录、音频分析才要的 Pillow / numpy / soundfile / scipy / faster-whisper / av / pypinyin / requests，并注明「配音走本地 GPT-SoVITS HTTP，不需要 torch」；
- `tools/check_syntax.py`：编译全部自有 Python（跳过 vendor / node_modules / projects 素材代码）；
- `tools/check_links.py`：查 README、CONTRIBUTING、CHANGELOG、SECURITY、CODE_OF_CONDUCT、docs/pipelines.md 的相对链接，以及 `site/index.html` 引用的 `media/*`；
- `.github/workflows/contract.yml`：push main / PR / 手动触发，跑四道门——`check_syntax` → `validate` → `sync_runtime --check` → `check_links`。

**本地实测**：

```
python tools/check_syntax.py   → 编译 218 个文件，失败 0 个
python tools/validate.py       → OK 契约一致
python tools/sync_runtime.py --check → OK 共享运行时一致（10 条管线）
python tools/check_links.py    → OK 文档与站点引用全部存在
```

**没验的**：这条 workflow 还没在 GitHub Actions 上真跑过（下一次 push 才是首跑）。

## ④ 字体单份化 + KaiTi 授权

**改前的账**：字体 146.4 MB。`NotoSerifSC.ttf` 2 份 47.9 MB、`KaiTi.ttf` 4 份 44.9 MB（微软系统字体，不能再分发）、
`AlibabaPuHuiTi-3-85-Bold.ttf` 5 份 39.9 MB、`LongCang` 2 份 9.8 MB、`LXGWMarkerGothic` 1 份 3 MB。仓库没有 `THIRD_PARTY_NOTICES.md`。

**为什么不能只留一份 + 相对引用**：三个渲染器（新版 / legacy / mg）都只服务**工程目录**这一个根，
字体必须物理待在工程目录里，`../../../assets/fonts` 会被服务器的路径守卫挡成 403。

所以是「仓库单份 + 渲染前复制」：

- `assets/fonts/` 只存一份：`NotoSerifSC.ttf`（23.97 MB）、`LXGWWenKai-Regular.ttf`（23.6 MB，OFL，楷体替代）、
  `AlibabaPuHuiTi-3-85-Bold.ttf`（7.98 MB）、`LongCang-Regular.ttf`（4.92 MB）、`LXGWMarkerGothic-Regular.ttf`（3.04 MB）；
- `tools/sync_fonts.py`：登记 8 条管线的 14 个落点，渲染前按需复制；`--check` 只比不写（CI 用），`--pipeline` 单条；
- **`KaiTi.ttf` 不再入库**：从本机系统字体取（`BV_FONT_KAI` → Windows `simkai.ttf` → macOS `STKaiti` → Linux `ukai`），
  没有系统楷体就降级到霞鹜文楷。本机字形和以前一模一样，但仓库不再分发微软字体；
- 14 个复制出来的落点全部写进 `.gitignore`，`git status` 不会变脏，也不会把系统楷体悄悄提交回去；
- 9 个入口脚本（`jianying_shotcraft` / `lishi` / `shouhui` / `shuimo` / `dengju` / `shiliang` / `xianshiqi` / `xuni` / `build_full`）
  在 `main()` 前挂了一次 `_ensure_fonts("<管线>")`，忘了手动同步也不会 404；
- 新增 `THIRD_PARTY_NOTICES.md`：5 款字体的授权、楷体的处理方式、样片与运行时依赖的归属。

**结果**：入库字体从 146.4 MB 降到 63.5 MB（单份），其中楷体 44.9 MB 直接清零；工作目录里因为多出一份 `assets/fonts`，
磁盘占用看着变高，但 git 里的体积是净减 82.9 MB。
